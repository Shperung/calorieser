# commit

Повідомлення будується лише з того, що в index (staged). Unstaged і untracked зміни не впливають на повідомлення і в коміт не потрапляють.

## Кроки

1. **Є що комітити?** `git diff --cached --quiet`. Код 0 означає, що staged порожній: сказати про це і зупинитися. Самому нічого не додавати: без `git add`, `git commit -a` і `git commit <шлях>` (останній комітить файл разом з unstaged-змінами).

2. **Зміст — тільки зі staged:**
   - `git diff --cached --stat`;
   - `git diff --cached`; якщо diff великий — по файлах (`git diff --cached -- <файл>`), а lock-файли й згенероване — лише за `--stat`;
   - стиль — `git log --format=%s -15`.

   `git diff` без `--cached` і вміст робочих файлів для повідомлення не використовувати.

3. **Повідомлення:**
   - мова, регістр і форма — як в останніх комітах репозиторію. Тут це переважно один рядок англійською з малої літери, дієслово в наказовому способі, без префіксів типу `feat:` і без крапки: `add server plan`, `update AGENTS.md`. Якщо історії немає — так само;
   - до 72 символів: що змінилось і навіщо, а не перелік файлів;
   - тіло (порожній рядок, далі пункти) — лише коли staged містить кілька незалежних змін, які не вміщаються в один рядок;
   - без `Co-authored-by`, підписів агента й emoji.

4. **Показати й спитати.** Повідомлення — у блоці коду, staged-файли — коротко зі `--stat`. Окремо, лише для інформації, назвати, що лишиться поза комітом: у `git status --short` це файли з непорожньою другою колонкою (є unstaged-зміни) і `??` (untracked). Спитати: комітити, змінити повідомлення чи скасувати. Без відповіді «так» не комітити.

5. **Коміт після «так»:**
   - якщо `git diff --cached --stat` уже інший, ніж на кроці 2, — сформувати повідомлення заново і знову спитати;
   - `git commit -F - <<'EOF'` … `EOF` — комітиться тільки index. Без `--amend`, `--no-verify` і `push`. У Cursor Shell для `git commit` потрібен дозвіл `git_write`;
   - якщо впав pre-commit хук — показати помилку, не обходити її;
   - наприкінці — `git log -1 --stat --format='%h %s'`.

## Обережно

Якщо серед staged є `.env*`, `*.pem`, `*.p8`, `*.p12`, `*.key`, `*.jks`, `*.mobileprovision` або щось схоже на ключі й паролі — назвати ці файли і не комітити без окремого підтвердження.
